# 协作与文档约定

当前默认不为每次修改创建规格、任务、审查报告和完成台账。短任务直接在对话中编排；只有用户要求或长任务确有协调需要时才建立临时本地记录，结束后将长期约束合入现有文档并删除过程记录。不要自动向外部平台发布。

多 agent 工作先明确文件所有权与依赖；按用户要求选择并行或串行。提交前检查已有未提交改动，每次实现或补改后复审整体调用链、异常、并发和架构简化机会；不能为形式上的重构增加抽象。

交付分别说明代码审查、静态检查、测试执行和部署证据。未运行的验证不得写成通过；本地完成不代表线上生效。业务术语与关键决策统一在 [架构文档](../architecture/ARCHITECTURE.md) 维护，避免词汇表和 ADR 重复存储同一合同。

文档以少为宜：根 AGENTS.md 负责导航，核心专题负责长期合同，代码中的必要注释解释局部职责；不生成逐目录地图和逐次变更日志。修改代码后同步受影响契约，完整字段/端点以代码及权威 API 文档为准。
