# 并发登录保留较新的成功状态，迟到成功仍可完成登录

同一账号先提交认证 A、后提交认证 B，两次都得到学校明确成功时，如果 B 已先提交成功状态，迟到的 A 仍返回本服务登录成功，但不能覆盖 B 的密码、学校凭证或交互标记。若 B 失败，则它的存在不阻止 A 提交成功。

这一选择将“本次身份已经验证成功”与“本次结果是否有权替换账号的最新认证状态”分开：用户无需因并发完成顺序重试，持久化事实也不会倒退。排序必须以认证尝试的先后关系为依据，不能仅使用完成时间或提交时递增的 epoch。

已通过 SchoolAccess 在途认证序号与 SQLite 短事务条件提交实现。静默恢复继续受开始时的认证上下文约束；它不能借迟到成功覆盖较新的真实登录，也不能补写旧交互要求。验证码续提分配新的认证序号；首次用户只在 CAS 成功事务中按唯一学号创建，同学号在途组在最后一次认证结束后回收。
