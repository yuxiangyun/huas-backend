# 07：账单与电费共享会话快照，独立使用请求时间

**What to build:** 校园卡账单和电费恢复可合流，每个请求按自己的预算发送业务请求，不再拿到首个请求的 HttpClient；所有读取仍遵守原有业务合同。

**Blocked by:** 04：使用已实现的统一 Portal 目标恢复；通用执行能力由 03 提供。

**Status:** completed

## Acceptance criteria

- [x] 并发共享结果不含 HttpClient 或可变 CookieJar；业务调用独立持有客户端、截止时间和等待超时。
- [x] 共享恢复自身有上限，短等待者超时不取消其他调用、不记共享故障；保留单次调用 20 秒预算。
- [x] 三类交易分页、电费 config→account 使用具名只读操作，最多一次会话恢复重放。
- [x] 保留最小 Cookie codec、epoch/generation 条件删除、月份和 20 页限制、6 个 LRU 月缓存、独立配额及双子源 freshness。
- [x] 保留电费位置 code 的传递、负电量、nullable 电价电量和关闭的支付能力；不修改解析规则。
- [x] 二次拒绝和版本竞争耗尽不误报交互认证；删除旧 mobile-yxt 重试恢复分支，生产类型检查通过。

## 验证边界

只允许生产源码类型检查和静态审查。不新增、不读取、不修改、不运行测试，不使用临时复现脚本替代测试，不访问学校上游或生产数据。

## 实施证据

交易分页、电费 config/account 通过 SchoolAccess；20 秒业务预算独立于共享恢复45秒。最小 Cookie codec、generation/epoch、分页、缓存、配额及纯解析规则保留。旧 executor 已删除。 生产类型检查通过；仅有静态证据，未读写或运行测试。最终两轴审查见任务 08。
