# 05：迁移其余 JW 读取和不可重放的评教提交

**What to build:** JW 课表、空教室、评教发现及提交走具名操作。读取可恢复，提交只发一次；业务保持既有课表及评教结果。

**Blocked by:** 03：使用 JW 目标恢复与统一操作执行器。

**Status:** completed

## Acceptance criteria

- [x] 课表、空教室、评教发现/读取成为具名只读操作；服务账号身份和请求用户保持原有边界。
- [x] 保留未公布与合法空表区分、来源回退、周日缓存、正常与强刷合流及有序提交。
- [x] 评教准备与实际 POST 使用同一会话，由 SchoolAccess 内部持有；应用层不接收或返回 HttpClient。
- [x] 固定一次批次目标；POST 一经尝试不得自动重放或把整个批次包入 retry。
- [x] 提交后只通过回查确认增量；无增量或验证失败保持 unknown，验证失败的旧快照标记不丢失。
- [x] 清除 Academic 的 HTTP callback、凭证与重试参数端口，保留领域可理解的具名来源操作。
- [x] 生产类型检查通过；静态检查明确覆盖所有写操作的不可重放边界。

## 验证边界

只允许生产源码类型检查和静态审查。不新增、不读取、不修改、不运行测试，不使用临时复现脚本替代测试，不访问学校上游或生产数据。

## 实施证据

JW 周课表、空教室、评教发现/列表/单项提交均具名化。表单与 POST 使用模块内同一客户端；批次目标、增量回查及 unknown 留在 Academic。 生产类型检查通过；仅有静态证据，未读写或运行测试。最终两轴审查见任务 08。
