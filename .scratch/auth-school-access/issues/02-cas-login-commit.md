# 02：CAS 成功立即登录，并发成功不回滚账号状态

**What to build:** 用户在 CAS 明确认证成功后即可完成本服务登录，资料及学校能力按需获取；并发成功均可返回 JWT，但账号持久状态只接受有权提交的成功结果。

**Blocked by:** 01：复用已固定的交互与学校故障语义。

**Status:** completed

## Acceptance criteria

- [x] CAS 成功后的 Portal 重定向、Portal/JW 激活和资料回填全部移出登录关键路径，不新增后台预热。
- [x] 建立 SchoolAccess 的学校认证边界，Identity 只处理本地快捷和本服务登录结果。
- [x] A 先开始、B 后开始且 B 先成功落库时，迟到成功 A 仍返回成功，不回写密码、凭证或交互标记；B 失败不阻止 A。
- [x] 首次同学号并发只产生一个用户；学校认证失败不得创建有效身份。
- [x] 真实登录与旧静默恢复通过共享提交原语及版本条件隔离；保留 epoch、派生清理与 Portal-only 不改 JW 的合同。
- [x] 成功响应保留 token、user、studentId；姓名班级可空；本地快捷不推进 epoch、不清冷却。
- [x] 更新登录 API、L3/L2/L1 与已接受 ADR 的实施状态，生产类型检查通过。

## 验证边界

只允许生产源码类型检查和静态审查。不新增、不读取、不修改、不运行测试，不使用临时复现脚本替代测试，不访问学校上游或生产数据。

## 实施证据

Identity 登录服务仅匹配本地密码或消费 SchoolAccess 身份。AuthEngine 在成功票据处立即返回；AuthenticationAttempts 与 StateStore 在同步事务提交前控制新旧候选。 生产类型检查通过；仅有静态证据，未读写或运行测试。最终两轴审查见任务 08。
