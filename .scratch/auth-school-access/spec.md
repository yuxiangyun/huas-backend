# 后端身份认证与学校访问简化规格

状态：用户已确认规格、8 项任务与本地 Markdown 保存方式；实现与两轴静态验收完成（见 review.md）。生产源码基线：`70b858ff8e25b2a0461afce931a42ec4e72038b2`。

## Problem Statement

用户可能在学校已确认身份之后仍因门户或教务故障无法进入本服务；相同请求重试又可能通过本地快捷登录。学校服务故障有时被映射为需要重新登录，客户端因此反复退出。并发真实登录可能让迟到结果覆盖较新成功状态，共享恢复还可能把首个请求的时间预算传播给其他请求。

维护者修改一种失败语义需要跨多个恢复与重试入口同步，业务调用方仍能看到凭证链和上游客户端，增加遗漏和重复调度的风险。

## Solution

在身份认证与学校访问范围内收敛三个对外边界：Identity 管理本服务登录；SchoolAccess 负责学校身份认证和具名学校操作；RuntimeConfig 一次解析并提供只读运行规则。其他业务模块继续保留。

CAS 明确认证成功即可完成本服务登录。学校资料和业务能力按需获取，首次资料为空也允许登录。学校明确拒绝已保存凭据或要求验证码时仍清除整个客户端登录态；学校普通故障保留登录并返回该能力不可用。

保留现有学校协议知识、缓存策略、条件提交与删除、epoch、generation、并发合流和禁止重复提交的约束，替换职责重叠的编排。

## User Stories

1. 作为首次登录用户，我希望学校身份验证成功后即可进入本服务，即使门户和教务暂时不可用。
2. 作为已有用户，我希望无交互认证要求时继续使用本地快捷登录，不因普通学校故障额外等待。
3. 作为用户，我希望姓名和班级暂缺不妨碍登录，资料在需要展示时再获取。
4. 作为 Web 用户，我希望登录后仍进入原有目标或树洞，保留当前空资料展示。
5. 作为小程序用户，我希望登录后仍进入课表首页；学校不可用时看到错误，而非立刻再次退出。
6. 作为用户，我希望只有学校明确拒绝已保存凭据或要求验证码时，才被要求整体重新登录。
7. 作为用户，我希望重新完成真实认证后解除交互要求，不再反复命中错误的快捷路径。
8. 作为并发登录用户，我希望两次均已验证成功的请求都可以完成本服务登录，较晚返回的旧请求不覆盖较新成功状态。
9. 作为用户，我希望较新的登录尝试失败时，不抹去较旧尝试已经得到的成功结果。
10. 作为用户，我希望过期验证码会话立即失效，其结果不依赖后台清理任务何时运行。
11. 作为用户，我希望学校页面缺少认证字段或返回普通 403/429 时，系统正确报告学校故障，不累计密码失败或驱动错误重登录。
12. 作为查询成绩的用户，我希望只恢复成绩所需的教务能力，不因无关门户故障失败。
13. 作为查询校园卡或移动课表的用户，我希望只恢复门户和对应派生会话，不顺带激活或改写教务会话。
14. 作为并发请求用户，我希望每次请求保留自己的剩余等待时间，不继承其他请求的客户端或截止时间。
15. 作为用户，我希望一个请求等待超时不取消其他请求的恢复，也不把自己的预算耗尽记成整个账号的学校故障。
16. 作为用户，我希望学校会话被拒绝后最多恢复并重放一次，重放仍失败时得到学校能力不可用。
17. 作为提交评教的用户，我希望系统不会因统一重试而重复提交，提交结果不确定时保持明确的未知结果。
18. 作为维护者，我希望新增一个学校能力时只定义该能力的协议与重放资格，业务层无需拼接凭证恢复链。
19. 作为维护者，我希望时间单位、次数、零值和默认值在配置边界明确，执行中使用同一配置快照。
20. 作为维护者，我希望迁移一个调用方就移除其旧编排，最终不存在两套长期并行的恢复状态机。

## Implementation Decisions

### 已确认的产品契约

- CAS 成功立即登录；学校资料与能力按需获取；不由登录触发后台预热。
- 学校明确拒绝已保存凭据或要求验证码：沿用客户端整体退出并重新登录的行为。这里不引入服务端全设备 JWT 撤销。
- 并发真实登录 A 先提交、B 后提交，B 的成功状态先落库后，迟到成功 A 仍可获得本服务 JWT，但不能覆盖 B。B 失败不构成阻止 A 成功提交的条件。
- 验收只做生产源码类型检查与静态审查；不新增、不读取、不修改、不运行测试，不以临时脚本绕过限制。

### 模块边界

- Identity 保留本地快捷校验、服务令牌和 HTTP 登录结果；学校身份认证交给 SchoolAccess。登录应用层不再激活 Portal/JW，不等待资料回填。
- SchoolAccess 只向调用方提供学校认证及具名学校操作。操作明确输入、输出、目标能力、只读或提交属性以及重放资格；不把任意 URL 或任意自动重试 callback 暴露给业务层。
- 恢复协调器、条件状态仓储、请求执行器和协议适配器是内部职责；不为每个职责复制一套目录层级，不引入通用工作流引擎。
- 保留现有具名业务接口可以实现兼容，但它们必须委托统一执行边界，不能继续向领域层泄漏客户端、门户 token、凭证目标或恢复次数。
- RuntimeConfig 管理静态运行规则；课表来源策略等动态业务配置继续由原模块拥有。凭证、交互标记、冷却与在途任务不属于配置。

### 登录与状态提交

- 成功判定继续依据现有 CAS 协议的明确成功证据，不把未知页面放行为成功。
- CAS 成功后的门户重定向不再是建立本服务登录态的前置条件；仅删除应用层显式激活步骤不算完成。
- 成功响应保持 token、user 对象和 studentId；name 可缺省、className 允许为空；不改变客户端跳转和默认资料展示。
- 本地快捷登录保持既有密码匹配与交互标记条件，不推进学校 epoch，不清除恢复冷却。
- 真实认证尝试在本次 CAS 认证开始前分配顺序；验证码续提是一次新的实际认证尝试。比较的是开始顺序和最近成功提交，不按完成时间决定新旧。
- 首次用户只能在学校明确成功后成为有效身份；同学号并发成功仍归并为一个用户。迟到候选只读取当前身份用于返回，不回写旧密码、凭证或交互标记。
- 当前生产单 writer 进程内，可用有界在途尝试记录协调首次用户的排序；最后一个相关尝试结束后回收。持久化更新仍必须在短事务中核对版本，不通过长期保留的无界 Map 实现。
- 真实登录和静默恢复使用同一提交原语，静默恢复额外受开始时 epoch 约束；真实登录先成功后，旧恢复不得覆盖或补写交互标记。
- 新真实认证按现有规则处理实际取得的基础凭证、缺失门户凭证和旧派生会话；Portal-only 恢复不得无差别清理或激活 JW。
- 优先使用现有存储结构和窄仓储接口，不在本轮进行表结构迁移；多 writer 部署不属于本轮目标。

### 学校访问、并发与预算

- 目标依赖固定为 CAS→Portal、CAS→JW、Portal→mobile-jw/mobile-yxt。JW 访问不前置依赖 Portal。
- 同用户 CAS 静默认证共享一次在途任务；同用户同目标会话获取共享一次在途任务。不同目标只共享必要的父认证，目标故障不阻断已成功的其他能力。
- 共享任务只返回不可变凭证或会话快照。每个调用方独立创建 CookieJar 副本、HTTP 客户端和绝对截止时间。
- 共享恢复使用自身有界执行预算，各等待者用自己的截止时间限制等待。某等待者超时不取消共享任务，也不写账号级故障冷却。
- HTTP 正文读取、等待、退避、恢复和业务请求全部纳入相应预算；耗尽后不启动下一步骤。保留成绩和 mobile 各自既有总预算，未显式提供总预算的通用学校操作也必须有明确默认上限。
- CAS 恢复失败按用户、目标能力失败按目标保留现有固定五秒冷却；绑定 epoch，命中不续期，保留错误原因。只有共享恢复本身耗尽或失败才写相应窗口。

### 失败与重试

| 事实 | 外部行为 | 自动处理 |
| --- | --- | --- |
| 真实登录 CAS 明确拒绝账号密码 | 保留既有登录失败合同 | 不重放 CAS POST |
| 已登录用户的 CAS 明确拒绝保存凭据或要求验证码 | 交互要求，沿用 3003/401 的整体退出 | 按 epoch 原子记录标记，真实认证成功清除 |
| CAS 普通 403/429、缺 execution、未知响应 | 学校不可用或协议异常，3005/503 | 不写交互标记，不累计密码失败；本轮不为 429 新增自动重试 |
| 网络或已明确可恢复的 5xx | 有界重试后 503 或 504 | 仅允许重放的步骤参与 |
| 某学校会话明确被拒绝 | 先按快照条件失效 | 必要时恢复，最多业务重放一次 |
| 新会话重放后仍拒绝、版本竞争耗尽 | 能力不可用或临时超时，不触发整体退出 | 条件删除坏快照，停止恢复循环 |
| 调用方等待期限耗尽 | 该请求超时 | 不取消其他等待者，不写共享学校故障 |
| 验证码会话到达有效期 | 拒绝消费并要求重新获取 | 读取时检查，清理任务仅回收内存 |

- 一套有穷错误分类表达交互需求、凭据拒绝、会话拒绝、不可用、超时与协议异常；null 只表示存储没有记录。
- 统一复用现有支持 code/cause 链的传输分类器；外部映射不靠各层各自猜字符串。
- 只有统一请求执行器调度重试。CAS 登录 POST 和评教提交不自动重放；读 GET 与已验证只读的 mobile POST 才能有界重试。
- 两个 mobile 当前把二次会话失效与部分并发竞争映射成凭据拒绝的分支必须同步修正；仅修 Portal/JW 不满足整体退出契约。
- 验证码有效期保留十分钟和一次消费，按当前时间达到到期点即失效。缺 execution 或验证码初始化的学校故障不计作用户密码失败。

### 配置

- 启动时一次解析并校验认证、重试、超时、冷却和验证码相关规则，产出只读快照；不借本轮重写整个应用的配置体系。
- 正整数规则拒绝分数、非有限值和越界值；可为零的延迟、抖动等参数单独声明零值含义，不再先判正数再向下取整。
- 未提供配置继续使用明确默认值；无效的显式认证配置应明确报错，不能静默形成零预算或无限重试。保留已有合法配置的含义及时间单位。
- 基础凭证 TTL 保持正整数；派生学校会话保留既有无猜测 TTL 合同。

### 迁移与保留边界

- 从真实登录和一个 JW 读取切片建立新边界，再迁移其他 JW、Portal、两个 mobile 的具名操作。
- 过渡适配只允许单向委托，每个切片完成即删除该调用方的旧恢复/重试分支；最后清点所有生产消费者并删除旧编排。
- 保留课表来源顺序、范围外与未公布语义、成绩 fresh-first、缓存/stale、资料有序回写、月交易分页、电费解析、日历独立刷新窗口、评教提交未知结果等已有业务契约。
- L3、所属模块 L2、根地图及 API 文档与实现同批更新；ADR 的 implementation 状态在对应实现完成后更新。

## Testing Decisions

本轮禁止读取、修改、新建或执行测试文件，禁止运行测试或复现脚本，不调用学校上游、不进入生产验收。

允许的验证是生产源码 TypeScript 检查、差异空白检查与静态契约审查。现有后端类型检查只包含生产源码，可以直接使用；包含测试的完整质量门禁不可运行。

静态审查集中于三个外部边界：登录结果及原子提交、具名学校操作及错误映射、启动配置及请求快照。审查逐条追踪上表与并发时序，检查一个逻辑规则是否仍散落在多处，以及迁移后是否存在旧入口消费者。

最终 code-review 分规范与规格两轴，子审查也受同样的禁止测试限制。类型检查通过或静态审查无发现不能被表述为并发、真实学校协议或完整客户端链路已通过运行验收；既有测试可能仍表达旧契约，本轮不检查其适用性。

## Out of Scope

- 安全加固、安全问题审查、密码存储方案重做及服务端全设备会话撤销。
- 新数据库表、schema migration、部署、推送、生产数据操作、真实学校登录或网络实测。
- Web/小程序 UI 调整、登录后跳转改造，以及 Web“我的”学校资料失败时隐藏社区编辑入口的问题。
- 日历、课表来源策略、业务缓存、限流额度、学校解析规则或未验证接口的功能扩展。
- Redis、消息队列、微服务、通用工作流引擎及多 writer 协调。
- 读取或改动用户已有的技能编辑内容；不得覆盖现有无关工作区修改。

## Further Notes

本轮不承诺线上行为已验证。学校普通故障下，小程序仍会进入课表首页显示错误；Web“我的”资料卡仍可能局部不可用，这是保留当前客户端的明确限制。
